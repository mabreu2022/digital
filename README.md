# Plataforma Enterprise de Digital Signage (Estilo Samsung MagicINFO)

Plataforma profissional de TV Corporativa / Mural Digital / Digital Signage desenvolvida em **Free Pascal / Lazarus** com banco de dados relacional **Firebird 5.0**.

---

## 1. Visão Geral da Arquitetura

O sistema é dividido em duas frentes modulares de alta performance:

                  |               SERVIDOR CMS / API REST              |

                  +-------------------------+--------------------------+
                                            |

                                            |
                                            v
                  +----------------------------------------------------+
                  |            BANCO DE DADOS FIREBIRD 5.0             |
                  | - Dialeto 3 / Charset UTF8                         |
                  | - BIGINT IDENTITY PKs                              |

## 3. Especificação do Banco de Dados (Firebird 5.0)

- **Dialeto**: 3
- **Charset / Collation**: UTF8
- **Primary Keys**: `BIGINT GENERATED BY DEFAULT AS IDENTITY`

### Principais Tabelas:
1. **`TELAS`**: Cadastro de hardware, UUID, IP Local/Público, Versão do Player, Último Heartbeat, Dimensões e Status (`ONLINE`, `OFFLINE`).
2. **`MIDIAS`**: Catálogo de arquivos com `HASH_MD5` único, tamanho em bytes, tipo (`VIDEO`, `IMAGE`, `HTML`, `STREAM`), duração padrão em segundos e URL de download.
3. **`PLAYLISTS`**: Agrupadores de conteúdos com flag de playlist padrão (`IS_PADRAO`) e status.
4. **`PLAYLIST_ITENS`**: Vínculo N:N ordenado entre Playlist e Mídia, com duração customizada de exibição e tipo de transição.
5. **`AGENDAMENTOS`**: Grade de eventos com `DATA_INICIO`, `DATA_FIM`, `HORA_INICIO`, `HORA_FIM`, `DIAS_SEMANA` (máscara binária ex: `0111110`), `PRIORIDADE` e `ATIVO`.
6. **`LOGS_EXIBICAO`**: Registros auditáveis de Proof-of-Play (PoP) com timestamp inicial/final, segundos efetivamente exibidos e status de conclusão.

## 4. Funcionamento do Motor do Player (Lazarus)

### 4.1. Modo Kiosk
- O formulário principal opera sem bordas (`BorderStyle = bsNone`), maximizado (`WindowState = wsMaximized`) e fixo no topo (`FormStyle = fsStayOnTop`).
- O cursor do mouse é ocultado via API nativa (`uKioskUtils.pas`).
- O protetor de tela e o descanso de tela do sistema operacional são suprimidos (`SetThreadExecutionState` no Windows e `xset s off -dpms` no Linux).
- Para sair do modo Kiosk, pressione `ESC` ou `Ctrl + Q` e informe a senha de administrador configurada.

### 4.2. Motor de Vídeo libvlc
- A inicialização do motor libvlc carrega dinamicamente a `libvlc.so.5` (Linux) ou `libvlc.dll` (Windows).
- São aplicados parâmetros de aceleração por hardware: `--avcodec-hw=any`, `--no-video-title-show`, `--no-audio-visual`, `--quiet`.
- O player vincula a saída de vídeo diretamente ao Handle do controle LCL (`TPanel`).

### 4.3. Operação Offline-First & Integridade de Cache
- O player nunca realiza streaming direto de arquivos pesados.
- Todas as mídias da grade são baixadas antecipadamente para o diretório `/cache/media`.
- A integridade de cada arquivo é estritamente validada via **MD5 Checksum** antes de ser liberado para exibição.
- Em caso de queda ou oscilação de rede, o Player continua executando a grade local sem qualquer interrupção.

### 4.4. Scheduler Local em Tempo Real
- A cada segundo ou ao término de um vídeo, o Scheduler avalia:
  1. A data e hora atual do sistema.
  2. O dia da semana atual.
  3. As janelas horárias ativas.
  4. A prioridade numérica dos agendamentos concorrentes.
  5. Fallback automático para a playlist padrão caso não haja eventos programados para o instante.

### 4.5. Proof-of-Play e Telemetria
- Cada mídia iniciada e finalizada é registrada em um buffer persistente local (`pop_buffer.json`).
- O worker de background envia os registros em lotes periódicos (`POST /api/v1/players/{uuid}/proof-of-play`).
- Heartbeats periódicos reportam status da tela, IP e mídia em execução.

## 5. Endpoints da API REST do Servidor

| Método | Endpoint | Descrição |
|---|---|---|
| `POST` | `/api/v1/players/register` | Auto-registro ou atualização cadastral do Player |
| `GET`  | `/api/v1/players/{uuid}/sync` | Retorna grade horária, playlists e lista de mídias para download |
| `POST` | `/api/v1/players/{uuid}/heartbeat` | Atualiza telemetria, IP, status e espaço livre em disco |
| `POST` | `/api/v1/players/{uuid}/proof-of-play` | Ingestão em lote de logs de exibição |

## 6. Instruções de Compilação

### 6.1. Compilação no Linux (Ubuntu / Debian)
```bash
# 1. Instalar dependências da libvlc e do Firebird Client
sudo apt update
sudo apt install -y fpc lazarus libvlc-dev libvlccore-dev vlc libfbclient2

# 2. Compilar o Player
cd player
lazbuild --build-mode=Release Player.lpi

# 3. Compilar o Servidor
cd ../server
lazbuild --build-mode=Release Server.lpi
```

### 6.2. Compilação no Windows (x86_64)
```cmd
:: 1. Compilar via lazbuild no Prompt de Comando do Lazarus
cd player
lazbuild --build-mode=Release Player.lpi

cd ..\server
lazbuild --build-mode=Release Server.lpi
```
Certifique-se de copiar as bibliotecas `libvlc.dll`, `libvlccore.dll`, a pasta `plugins/` do VLC e `fbclient.dll` para a pasta `bin/` correspondente.
